## 1. Discrepancies and Errors in v2 Documentation

| **1** | **Statistical Significance of RLTR OLS ($t = 26.77$)**<br>`v2/RESULTS.md` Line 18, Table 2 | Stated $p = 4.24 \times 10^{-77}$ for $t = 26.772$. | Correct $p$-value is **$p = 3.97 \times 10^{-88}$** ($df = 365$). | Both values indicate infinitesimal probability ($p < 10^{-75}$). The exponent difference stemmed from floating-point evaluation in scipy/statsmodels across degrees-of-freedom approximations. |
| **2** | **Predictor Set for $t = 26.77$**<br>`v2/RESULTS.md` Line 18 | Stated: *"In multiple OLS regression controlling for Glucose and BMI, Outcome has an artificial coefficient of +28.68 mg/dL ($t = 26.77$)"*. | $t = 26.7724$ ($\beta = +28.6825$) is the **Full 8-Predictor Model** (controlling for Pregnancies, Glucose, BloodPressure, SkinThickness, BMI, DiabetesPedigreeFunction, and Age).<br><br>The model controlling *only* for Glucose and BMI yields **$t = 27.6409$** ($\beta = +28.8132\text{ mg/dL}$, $p = 5.19 \times 10^{-92}$). | Imprecise prose in v2 conflated the Base bivariate covariate set with the Full multivariate covariate set. |
| **3** | **Observed-Data Baseline Data Source**<br>`v2/RESULTS.md` Table 2, `run_phase2.py` | Stated: Evaluated on raw observed patients ($N=394$). | The Phase 2 script evaluated `df_obs = rltr[observed_ins]`, where missing values in `SkinThickness` had already been imputed by the RLTR algorithm, yielding $\beta = -5.72, t = -0.45, p = 0.653$.<br><br>When evaluated directly on unimputed raw data (`raw[observed_ins]`), the coefficient is **$\beta = -6.16\text{ mg/dL}$** ($t = -0.484, p = 0.629$). | Both confirm the absence of a conditional target signal in observed biology, but v2 used partially pre-imputed data for its observed baseline. |
| **4** | **Tolerance Parameter ($\epsilon$) in Honest RLTR**<br>`v2/RESULTS.md` Table 2 vs Table 3 | Table 2 reported Honest RLTR with $r = 0.5129, \text{MAE} = 33.66$. Table 3 reported Honest RLTR with $\epsilon = 0.25$. | Phase 2 script (`run_phase2.py`) evaluated Honest RLTR at **$\epsilon = 0.15$** (matching the published paper parameter), which produced $r = 0.5129, \text{MAE} = 33.66$. Phase 3 script (`run_phase3.py`) evaluated Honest RLTR at **$\epsilon = 0.25$** in its 50-fold cross-validation benchmark ($0.7671$ accuracy). | The tolerance threshold shifted from $0.15$ in Phase 2 to $0.25$ in Phase 3 without explicit documentation in v2. |
| **5** | **Misclassification of Imputation Family Names**<br>`README.md`, `EXECUTIVE_SUMMARY_REPORT.md` | Mislabeled all 5 files as parametric trend or spline regressions:<br>- `TR`: *"Trend Regression"*<br>- `LTR`: *"Linear Trend Regression"*<br>- `RLTR`: *"Robust Linear Trend Regression"*<br>- `NSSR`: *"Non-linear Spline Regression"*<br>- `SIM`: *"Simple Imputation Method"* | All 5 files are **Rough-Set Similarity and Tolerance Relations** derived from rough-set theory:<br>- **`TR`**: **Tolerance Relation**<br>- **`LTR`**: **Limited Tolerance Relation**<br>- **`RLTR`**: **Relative Limited Tolerance Relation**<br>- **`NSSR`**: **Non-Symmetric Similarity Relation**<br>- **`SIM`**: **Similarity Relation** | Fundamental misnomer in v2 narrative. The methods are non-parametric rough-set approximations based on relational tolerance matrices, not parametric statistical regressions. |
| **6** | **R_max Footnote Withdrawn**<br>`v2/RESULTS.md` Footnote, Table 2 | Claimed $R_{\max} = 0.5299$ proved RLTR exceeded linear correlation bounds, and linked it to LTR. | **Formally Withdrawn**. If LTR insulin were a linear function of $X$ with $r(I, \hat{y}) = 0.909$, then $r(I, Y) \le 0.909 \times R_{\max}(\text{LTR features}) = 0.909 \times 0.5374 \approx 0.488$. The observed $r = 0.5299$ exceeds $0.488$, meaning a non-linear component of LTR insulin correlates with Outcome. Furthermore, $0.5299$ (raw-feature $R_{\max}$) and $0.909$ (LTR-feature $\hat{y}$) used different feature sets. The four-decimal match with the raw-feature bound is coincidental. | $R_{\max}$ bound comparisons are formally removed from all v3 benchmarks and conclusions. |
| **7** | **MissForest Performance Gain Claim**<br>`v2/RESULTS.md` Table 3 | Claimed MissForest achieved +1.12 pp accuracy over Median imputation. | v2's "MissForest +1.12 pp" compared different classifiers; with a fixed classifier, MissForest is equivalent to median ($\Delta\text{AUC} \approx +0.0010, p = 0.442$ for LogReg; $\Delta\text{AUC} \approx +0.0001, p = 0.987$ for XGBoost). | Imputation strategy comparison in v2 conflated model architecture shifts with imputation effects. Rigorous controlled testing across 50 outer folds proves no detectable discriminatory gain. |
| **8** | **Operating Decision Threshold Selection ($\tau = 0.37$)**<br>`v2/RESULTS.md`, `EXECUTIVE_SUMMARY_REPORT.md` | Claimed optimal threshold $\tau = 0.37$ yields $79.85\%$ sensitivity and $75.20\%$ specificity on out-of-fold data. | Threshold $\tau = 0.37$ was **chosen and evaluated on the same out-of-fold predictions**, introducing post-hoc threshold selection leakage. When evaluated strictly under **nested 50-fold cross-validation** (inner-fold threshold tuning, evaluated on unseen outer fold; Experiment E5), Policy B ($\text{Sensitivity} \ge 0.80$, inner mean $\tau \approx 0.280$) achieves **$\text{Sensitivity} = 0.8043$ and $\text{Specificity} = 0.6848$** ($F_1 = 0.6725$, accuracy $72.65\%$). Under default $\tau = 0.50$, sensitivity is $0.5580$ and specificity is $0.8788$. | Post-hoc threshold selection without a nested validation loop artificially inflates perceived specificity at high sensitivity by capitalizing on chance fluctuations. |
| **9** | **Leak-Free Insulin Feature Importance Rank (#2)**<br>`v2/RESULTS.md`, `EXECUTIVE_SUMMARY_REPORT.md` | Claimed Insulin remained the #2 most important feature even under leak-free modeling. | In v2 Phase 5 (`v2/scripts/run_phase5.py`), this was derived from a single 5-fold cross-validation run using MICE, RobustScaler, and CatBoost:<br>`imp = IterativeImputer(estimator=BayesianRidge(), max_iter=10, random_state=42)`<br>`scaler = RobustScaler()`<br>`cb = CatBoostClassifier(iterations=200, depth=4, learning_rate=0.03, verbose=0, random_seed=42)`<br>which yielded out-of-fold mean \|SHAP\| of Glucose 0.6324, Insulin 0.4516, BMI 0.4188.<br><br>Under **200 bootstrap refits** on the 614 training rows (Experiment E7): in the final model (LogReg-L2, median), Insulin has a **median rank of 6.0 / 8** (IQR 2.0, top-3 frequency $1.0\%$, standardized coefficient mean $-0.0695$); in leak-free Tuned XGBoost, Insulin has a **median rank of 5.0 / 8** (IQR 2.0, top-3 frequency $3.5\%$). Dominant features across both models are Glucose (median rank 1.0, 100% top-3) and BMI (median rank 2.0, 100% top-3). | Single-split feature importance estimates without confidence intervals can be misleading; once Glucose and BMI are known, Insulin contributes negligible incremental discriminatory signal in resampled models. |
| **10** | **Holdout Test Set Performance ($74.68\%$ Ensemble)**<br>`v2/RESULTS.md`, `README.md` | Stated: Complex stacking ensemble achieved $74.68\%$ on the frozen holdout test set ($n=154$). | The v3 final model—a parsimonious, leak-free **LogReg-L2 default** with in-fold median imputation and StandardScaler (selected under Protocol Amendment 2)—achieves **$70.78\%$ accuracy** ($82\text{ TN}, 18\text{ FP}, 27\text{ FN}, 27\text{ TP}$) and **$\text{ROC-AUC} = 0.8130$** on the seed-42 holdout split (`train_test_split`, `test_size=0.20, random_state=42, stratify=y`), compared with the v2 ensemble's reported $74.68\%$ on its holdout. Across 100 random splits, LogReg-L2 averages **$76.60\% \pm 2.62\%$ accuracy** and **$0.8369 \pm 0.0267$ ROC-AUC**. | On seed 42, LogReg-L2 is $70.78\%$ vs v2 ensemble $74.68\%$ (a difference of 6 classification decisions on $n=154$). Across 100 random split seeds, LogReg-L2 exhibits a distribution centered at $76.60\%$ (95% percentile interval: $70.78\%\text{–}81.51\%$). |
| **11** | **Tree Depth Lower Search-Space Boundary Hits in E4**<br>`v3/results/E4_hyperparameter_stability.csv` (Methodological Limitation) | Not previously documented in v2. | In nested 50-fold cross-validation (Experiment E4), hyperparameter optimization consistently hit the minimum allowable tree depth: XGBoost `max_depth` (search range: $[2, 8]$) hit the lower bound ($=2$) in **$78.0\%$ ($39/50$)** of outer folds; CatBoost `depth` (search range: $[3, 8]$) hit the lower bound ($=3$) in **$68.0\%$ ($34/50$)** of outer folds. | On small clinical tabular data ($N=768, d=8$), deep trees rapidly overfit. The optimization favored heavily regularized, shallow architectures, consistent with linear logistic regression matching or exceeding gradient boosted trees ($p_{\text{TOST}} < 0.05$). This saturation represents a pre-registered search space limitation. |
